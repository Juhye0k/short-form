# 프롬프트·결과와 포트폴리오 근거 기록

> 프롬프트·결과와 포트폴리오 근거 기록에 속한 문서를 찾는 목차입니다. 아래 글의 설명을 읽고 필요한 주제로 이동하세요.



작업 기록은 무엇을 요청했고 어떤 결과를 얻었는지 다시 확인하기 위한 문서다. 페이지 맨 위에는 최종 결과를 요약하고, 아래에는 문제·진행 과정·실패 수정·검증 근거를 남긴다.


[위키 홈](../../../README.md) · [하네스 목차](../README.md)

사용자가 어떤 문제를 정의하고 AI에게 무엇을 요청했는지, 실제로 무엇이 바뀌었고 어떻게 확인했는지를 한 작업 단위로 남긴다. 이후 포트폴리오에서 문제 해결 과정과 본인의 판단을 근거와 함께 설명하는 데 사용한다.

## 기록 시점과 단위

1. 기능 구현·오류 수정·설계 결정·하네스 개선을 시작할 때 [양식](template.md)을 복사하고 맨 위에 핵심 요약을 쓴다. 기존 Issue·작업 ID를 우선 사용하고, 없으면 `날짜-주제`를 기록 ID로 정한다. 기록 ID를 실제 Issue 번호로 표현하지 않는다.
2. 목적·완료 기준, 공개 가능한 사용자 프롬프트, 시작 커밋과 기존 미커밋 변경 유무를 먼저 적는다. 작성 중에는 결과를 미확인으로 둔다.
3. 후속 수정·실패·사용자 결정은 P1, P2 순서로 같은 페이지에 추가한다. 각 요청에 대응하는 실제 산출물과 검증 결과를 연결한다. 작업 범위가 독립적으로 바뀌면 새 기록을 만들고 서로 링크한다.
4. 종료 시 상단을 최종 결과와 남은 작업으로 갱신하고, 실제 결과·미실행 이유·사람의 판단·AI 작업·포트폴리오 요약을 정리한다. 성공하지 못한 시도와 품질 미달은 단계별 상세 기록에 남긴다. 완료 보고에 기록 링크를 포함한다.
5. 아래 목차에 추가하고, 기존 기록을 갱신했다면 상태도 맞춘다. 단순 질의나 사소한 문구 수정은 관련 기록에 합치거나 기록 대상에서 제외한다.

현재 대화에서 확인할 수 없는 과거 프롬프트를 만들어 넣지 않는다. 과거 작업을 정리할 때는 출처를 붙인 요약으로 표시하며, 확인할 수 없는 항목은 `미확인`으로 남긴다. 기존 [실패·개선 기록](../changes/README.md)은 원인·회귀 검사의 상세 근거로 연결하고 중복 복사하지 않는다.

## 공개 가능한 입력과 증거

프롬프트는 사용자의 요청 중 공개 가능한 부분만 인용하고 `원문 발췌`, `일부 생략` 또는 `요약`으로 표시한다. 삭제·대체가 있었다면 그 사실을 적되 민감한 원래 값은 남기지 않는다. 원본 대화 전체, 시스템·개발자 메시지, 비공개 내부 추론, 토큰, 개인 경로, 사용자 영상·자막·로그는 공개 Git·Wiki에 넣지 않는다. 필요한 원본은 승인된 비공개 위치에만 보관한다.

결과에는 코드·문서·검사 파일·커밋·PR 등 다시 확인할 수 있는 링크를 붙인다. 미커밋 결과는 시작 커밋만으로 재현된다고 주장하지 않는다. 검사는 실행 명령·환경·관측 결과와 미실행 이유를 남기고, 명령의 성공과 제품 품질 통과를 구분한다. 공개 자료에는 민감정보를 제거한 요약만 사용한다.

모델·도구·사용량·비용·소요 시간은 관측한 값과 측정 범위만 적는다. 제공되지 않은 값은 `알 수 없음`으로 남기며 무료나 0으로 대신하지 않는다. 개발 에이전트 비용과 제품에서 호출한 외부 AI 비용은 구분한다.

## 포트폴리오에 옮길 내용

`문제·제약 → 사용자가 정한 방향과 판단 → AI가 수행한 작업 → 검증된 결과와 근거 → 남은 한계·배운 점`으로 정리한다. AI가 작성한 코드를 본인이 직접 작성했다고 바꾸거나, 에이전트가 선택한 구현 방식을 사용자의 결정으로 기록하지 않는다. 사용자 검수 여부를 알 수 없으면 미확인으로 둔다.

수치 성과에는 기준 입력·비교 대상·측정 방법을 붙인다. 전후 측정이 없으면 시간 단축률이나 품질 향상률을 만들지 않는다. 한 작업의 성공을 프롬프트나 하네스 전반의 개선으로 일반화하지 않는다. 비교 실험은 [작업 규칙](../../../../AGENTS.md)의 동일 조건 원칙을 따른다.

## Wiki 게시와 현재 한계

에이전트가 작업 중 이 절차에 따라 Markdown 기록을 갱신한다. 대화 자동 수집기나 성과 평가 시스템은 구현하지 않았다. 현재 대화 밖에서 입력한 프롬프트는 자동으로 가져오지 않는다.

`wiki/`는 게시 원본이다. GitHub Wiki 반영은 [문서 게시 절차](../../../07-governance/document-guide.md)에 따라 해당 승인 범위에서 수행하며, 게시한 경우 실제 페이지 링크와 확인 결과를 기록한다. 로컬 작성 완료를 원격 게시 완료로 표현하지 않는다.
