# 쇼츠 제작실 화면 개선 — FLOW-WEB-003

> 새 영상과 이전 프로젝트를 찾는 동선을 정리하고, 후보 목록·재생·편집 동작을 한 화면에서 이어간다.

사용자는 알파컷을 참고해 숏폼 제작실 디자인을 개선하고 별도 패널에서 진행해 달라고 요청했다. 시작 커밋은 `a241d28`이다. 기존 작업 트리의 변경과 분리된 제작실 작업 트리를 사용한다.

완료 기준은 데스크톱과 모바일에서 새 영상 입력, 프로젝트 재개, 후보 선택, 자막 편집과 출력 경로를 확인하는 것이다. 기존 링크·파일 접수와 사용자 확인 절차를 유지한다.

## 구현과 확인

[알파컷 제작 가이드](https://alphacut.video/blog/create-first-short)의 프로젝트 탐색과 후보 비교 흐름을 참고했다. 쇼츠 제작실의 작업 메뉴와 상태가 표시되는 프로젝트 목록을 만들었다. 후보 목록·영상·편집 동작에 각각 영역을 배정하고, 폭이 좁을 때 순서대로 배치했다. 자막 편집기와 YouTube 게시 화면에는 제작실과 같은 색상과 탐색 스타일을 적용했다.

저장소 표준 검사에서 Ruff, 기본 테스트와 Alembic 오프라인 SQL을 통과했다. 실제 Chrome의 390·768·1024·1440px에서 대역 응답을 사용해 로컬 파일 입력 열기, 프로젝트 재개, 후보 선택과 새로고침 복원, 편집·게시 화면 이동과 가로 넘침을 검사했다. Wiki 빌드에서 공개 문서 21편을 생성했다. 외부 AI 호출과 실제 게시에는 연결하지 않았다.

작업에는 Codex, Herdr, PowerShell, Python 3.12와 Playwright를 사용했다. 에이전트 사용량과 비용은 알 수 없다. 결정 근거는 후보를 비교하면서 미리보기와 다음 편집 동작을 바로 찾을 수 있는지였다.
